# SkillPath AI: правила для агентов

Контракт API, таблиц и страниц лежит в `ARCHITECTURE.md`. Дизайн: `docs/design/DESIGN.md`. Этот файл описывает, как работать в репозитории. Его читают все агенты (`lead`, `builder`, `auditor`) до начала работы.

## Стек и проверки

- Backend: `backend/`, Python 3.11+, FastAPI, SQLAlchemy 2, Alembic, pytest, ruff. Тесты идут на SQLite в памяти, поэтому несколько `pytest` можно запускать параллельно.
- Frontend: `frontend/`, Next.js 14, TypeScript, Tailwind.
- Проверка backend: `cd backend && python -m ruff check . && python -m pytest -q`. На время работы над задачей достаточно тестов затронутых модулей, полный прогон делает CI.
- Проверка frontend: `cd frontend && npm run typecheck && npm run lint`, затем `npm run build`, если менялись маршруты, конфиги или layout.
- CI (`.github/workflows/ci.yml`) гоняет всё: backend, frontend, сборку Docker. Красный CI не сдаётся владельцу.
- На этой машине запись `\b` в файлы через Bash/heredoc превращается в символ backspace. Для регулярок используйте lookaround или Edit-инструмент, и после правки проверьте файл.

## Доменные правила (нарушение = MUST)

- Паролей нет. Вход только через Google OAuth2; `dev-login` и `demo-login` работают лишь при включённых флагах и не выбирают роль из запроса.
- Роль admin выдаётся только по `ADMIN_EMAILS` (и общему демо-админу в `DEMO_MODE`). Все `/api/admin/*` закрыты `require_admin`.
- Уроки, тесты и ИИ доступны записанным на курс и админам. Без записи 403.
- Правильные ответы теста (`correct_index`, `explanation`) не уходят клиенту до отправки попытки. Оценка считается на сервере.
- ИИ-наставник: ключ RouterAI только на сервере. Вопрос проходит `ai_guard` до запроса к ИИ; `OFFTOPIC` и ответы со стоп-темами не показываются. Лимит на пользователя сохраняется, в демо добавляется общий дневной.
- Загрузка файлов: белый список расширений, имя файла генерирует сервер, ограничение размера.
- `JWT_SECRET` с дефолтным значением не стартует на не-локальном адресе. Это не ослабляем.
- Миграции Alembic обязательны при смене `models.py`; `alembic check` должен быть чистым. `models.py` не меняется молча: сначала обновляется `ARCHITECTURE.md`.

## Секреты и конфиденциальное

- В репозиторий, коммиты, PR и комментарии никогда не попадают: ключи (RouterAI, Google), токены, пароли, `.env`, адреса и порты серверов, имена пользователей и ключей SSH. Пишите `<server>`, `<user>`, `<key>`.
- Перед каждым `git push` и текстом для GitHub делайте `git diff` и ищите по нему IP, порты, `sk-`, `token`, `password`.
- Боевые серверы владельца (VPN-ноды и их конфиги) без прямого разрешения на конкретную задачу не трогаются, даже ради демо-стенда.

## Стиль

- Код: идентификаторы английские. Комментарии только там, где неочевидно «почему». Всё, что видит пользователь (интерфейс, ошибки, README, docs), по-русски.
- Текст без ИИ-слога: без лозунгов и пафоса, без эмодзи, без длинных списков с жирными ярлыками, без вступлений и итогов. Коротко и по делу, как пишет студент, который сам сделал проект.
- Меньше кода лучше: без хелперов на один вызов, без запасных опций «на будущее», без мёртвого кода, без дублирования существующих утилит.
- Тесты: по одному на поведение на самом высоком уровне, который его доказывает. Ничего не отключать и не ослаблять, чтобы стало зелёно.

## Деплой и ветки

- Работа идёт в ветках `fix/…`, `feature/…`, `chore/…`, `docs/…` от свежего `origin/main`. Прямых пушей в `main`, force-push и слияния PR агентами нет: слияние делает владелец.
- Демо-стенд ставится только по `docs/deploy-demo.md`; ключ RouterAI лежит лишь в серверном `deploy/demo.env` (в `.gitignore`).
