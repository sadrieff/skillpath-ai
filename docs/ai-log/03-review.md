# Ревью

Ревью делал Sonnet: прогон тестов и линтера, чтение критичного кода (авторизация, ИИ, тесты, загрузка), живой прогон API на настоящем сервере, сверка путей фронта и бэка.

## Найдено и исправлено

- **Дефолтный `JWT_SECRET`.** Значение `dev-only-change-me` позволило бы подделать токен администратора, если забыть задать секрет на сервере. Теперь приложение не стартует с ним на адресе, отличном от localhost. Тест: `backend/tests/test_startup_guard.py`.
- **Ruff против сгенерированного `models.py`.** Линтер ругался на файл-контракт. Добавлен `backend/ruff.toml` с исключениями для него и для длинных текстов в сиде.
- **Лендинг и навигация.** Первая версия прятала общую навигацию наложением на весь экран, это сломало прокрутку документа. Заменено на route groups: навигация лежит в `app/(app)/layout.tsx`, лендинг без неё.
- **Шрифт и палитра.** Предложенный скиллом Red Hat Display не содержит кириллицу, взят Onest. Фиолетовый акцент запрещён правилами taste-skill, заменён на лаймовый `#c8f169`.
- **Шаблонный текст.** README исполнителя был на 450 строк и называл проект дипломным. Переписан, журнал тоже.

## Проверено вручную на живом сервере

Вход, поиск, запись на курс, доступ к уроку до и после записи, тест (в выдаче нет `correct_index`), 422 на неполные ответы, 503 без ключа ИИ, 403 студента в админке, загрузка файла (имя `../../evil.pdf` не влияет на путь, `.exe` отклоняется), CORS только для адреса фронта. Пути фронта совпали с бэком: 22 из 22.

## Запрос к настоящему RouterAI

Прогнал через `ai_client.chat` с реальным ключом (модель `qwen/qwen3.5-flash-02-23`). Разбор ошибки в тесте пришёл по делу. Ответ идёт 10-15 секунд, один раз был ConnectTimeout (клиент возвращает 502, фронт показывает «сервис временно недоступен»).

Первая версия промпта давала шаблонный ответ с приветствием, утешениями и заголовками. Промпт переписан: без приветствий и похвалы, до 150 слов, без заголовков.

## Ограничение вопросов

Нужно было исключить вопросы вне урока, например про оружие. Одним промптом это не закрывается, поэтому три слоя (`backend/app/services/ai_guard.py`):

1. Стоп-список (оружие, взрывчатка, наркотики, вред людям, попытки сменить правила или вытащить системный промпт). Срабатывает до запроса к ИИ, ничего не уходит и не сохраняется. Ловит и обфускацию: точки между буквами, невидимые символы, цифры вместо букв.
2. В системном промпте модель обязана ответить `OFFTOPIC`, если вопрос не по уроку.
3. Сервер заменяет `OFFTOPIC` и ответы, попавшие в стоп-список, на фиксированный отказ.

Живая проверка: вопрос про столицу Австралии модель отсекла сама. Не ловится только смесь латиницы и кириллицы в одном слове («B0мба»), такие случаи остаются на втором слое. Тесты: `backend/tests/test_ai_guard.py`.

## Не проверено

- Вход через Google на реальном домене.
- Docker: на машине разработки его нет, образы и compose не собирались.
- Ветка поиска для PostgreSQL (на SQLite поиск идёт в Python из-за кириллицы).
- Страницы за авторизацией в браузере с запущенным бэкендом.
- Открытые пункты из `04-ui-audit.md`: защита от потери несохранённых форм, `required` у полей админки.

## Известные ограничения

- `ENABLE_DEV_LOGIN=1` даёт вход под любым email, в том числе администратором из `ADMIN_EMAILS`. Включать только для демо и локально.
- Токен после входа через Google передаётся в адресе (`?token=`), так он попадает в историю браузера. Для учебного проекта оставлено.
- Лимит запросов к ИИ считается по сохранённым ответам, параллельные запросы могут его слегка обойти.

## Публичный стенд

Поднят на общей ноде по адресу https://demo.ciferkaservice.online:8443. Образы собирает GitHub Actions, нода их только скачивает; у контейнеров лимиты памяти и процессора, стенд занимает около 135 МБ. Конфиги соседних сервисов не менялись.

Проверено через публичный адрес: демо-вход, прохождение теста, разбор ошибки настоящей моделью, отказ на вопрос про оружие и на посторонний вопрос, 403 для студента в админке, ночной сброс (запущен вручную).

Что вышло не с первого раза:
- Проверка «порт 8443 занят» была ложной: локальный Happ-туннель отвечал «открыто» на любой порт, даже на случайный. Порт оказался свободным.
- certbot на Windows требует администратора, выпуск сертификата сделан в WSL.
- Автоматический HTTPS Caddy на нестандартном порту не работает (80 и 443 заняты Xray), сертификат выпущен вручную по DNS и продлевается вручную, см. `docs/deploy-demo.md`.
- Автозапуск деплоя по SSH падал на каждом пуше без секретов, оставлен только ручной запуск.
- После ночного сброса идентификаторы курсов в Postgres идут дальше (последовательности не обнуляются), тесты и скрипты не должны полагаться на id 1.
